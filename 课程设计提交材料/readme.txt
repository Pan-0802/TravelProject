二、首次运行
环境：JDK17或21、Maven、MySQL8.0.16+、Node20.19+或22.12+，Chrome或Edge。
1. 新电脑在Navicat连接MySQL，完整执行根目录schema.sql一次，创建travel_planner_course_demo及10张表和演示数据。
2. schema.sql会重建这个专用演示库。不要反复对保存了个人数据的演示库执行；原开发库travel_planner_course不受影响。原开发库升级只执行04聊天增量脚本。
3. 复制backend/.env.example为backend/.env.local，填写本机数据库端口、账号、密码和固定随机JWT密钥。高德与AI Key按需填写，仅放后端，真实本地配置不提交Git。
4. 根目录启动后端：powershell -ExecutionPolicy Bypass -File backend/scripts/Start-Backend.ps1
5. 根目录启动前端：cd frontend，然后npm ci、npm run dev，打开http://localhost:5173。
6. 数据库就绪检查：http://localhost:8080/health/ready，正常返回code为0、database为UP。
完整安装、配置和协作步骤以根目录README.md为准。

四、数据与AI口径
预计费用与实际消费独立。确认AI方案后才写入每日行程，覆盖已有安排须确认，原消费不被AI覆盖。
普通接口3秒未响应会给超时提示；AI先快速返回202受理，再轮询结果。202不等于生成完成，可以离开后回来查看。
未填写外部Key仍可使用基础功能和初始化草稿；生成新回复或实时高德搜索需要有效Key与网络。
自动距离预估此前因地点歧义移除，课件没有要求此功能。AI价格、地点和开放信息需要出行前人工核实。
数据库中的费用、时间和用户均为课程演示资料。报告标注的2026年11月25日多轮案例是历史验收，不冒充本次重新调用。
